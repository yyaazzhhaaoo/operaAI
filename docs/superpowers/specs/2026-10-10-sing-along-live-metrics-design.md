# 实时跟唱页（`sing_along.html`）实时节奏偏差与气息稳定性 实现设计

日期：2026-10-10 ｜ 状态：已评审待实现 ｜ 关联：《1-PRD-V1.0》2.9 / 2.10；`scripts/test_sing_along_algo.js`；`DOC_ISSUES.md` 第 41 条；`2026-10-09-sing-along-list-and-demo-playback-design.md`

## 1. 背景与目标

`sing_along.html` 的录音区有四张实时指标卡。其中**音准**已经是真的（`updateMetrics` 取离当前时刻 0.1s 内最近的学生落点，与教师该字的 `pitch` 求音分差，`:1333-1352`），另外两张——

- **节奏偏差 (秒)**（`#valRhythm`，`:595-599`）
- **气息稳定性**（`#valBreath`，`:601-605`）

—— 是**按当前唱到第几个字 `widx` 查表的硬编码值**（`:1354-1395`）：`widx===2` 就显示 `+0.08s / 72%`，`widx∈{0,1}` 显示 `+0.02s / 88%`，其余 `+0.03s / 82%`。与音频、与学生实际唱成什么样**毫无关系**。

**目标**：把这两张卡改成用真实录音数据计算，并让新写的算法**纳入 `scripts/test_sing_along_algo.js` 的覆盖范围**——这是本轮做这件事的起因：该脚本是页面「纯算法」段的唯一测试手段，而这两张卡之所以一直是假的，部分原因就是它们原先长在碰 DOM 的 `updateMetrics` 里，抽不进那个脚本。

**不做**：后端一行不动，不新增接口，不动停录后的评分流程。

## 2. 需求原文：PRD 2.9 / 2.10

《1-PRD-V1.0》对这两项有明确定义：

| 编号 | PRD 原文（摘自 `word/document.xml`） | 页面现状 |
|---|---|---|
| 2.8 实时音准偏差显示 | 当前字与老师音高差（音分）实时显示 | ✅ 已真实实现 |
| 2.9 **实时节奏偏差显示** | **当前字时值与标准值偏差（秒）显示** | ❌ 硬编码 |
| 2.10 **实时气息稳定性显示** | **长音段能量波动系数（%）显示** | ❌ 硬编码 |

2.9 要的是**时值**（一个字的持续时间），2.10 要的是**长音段**上的能量统计——两条都按原文实现，本轮不偏离口径。

## 3. 已确认的四个口径决策

以下四条在评审中逐条确认，是本设计其余部分的约束：

| # | 议题 | 决策 | 理由 |
|---|---|---|---|
| 1 | 字还没唱完时卡片显示什么 | **字结束时才定格**，进行中保持上一个字的最终读数 | DTW 的映射是全局路径算出来的，录音越长早期字的映射越可能被微调；定格在字结束能稳住读数 |
| 2 | 气息显示稳定度还是波动系数 | **主数显示稳定度 `(1−CV)×100%`，波动系数写进日志** | PRD 2.10 的字面是波动系数，但卡片名叫「气息稳定性」、停录后维度面板用的也是稳定度；两者方向相反，同页并存会让人以为哪个算错了 |
| 3 | 停录后卡片怎么办 | **重置为 `--`** | 卡片定位是「录音中的实时指示」，录音结束后的权威结论由维度面板承担，各司其职 |
| 4 | 长音还在唱时要不要实时刷 | **长音段结束才定格**，与决策 1 同构 | 半截数据的 CV 抖动大、且与停录后口径不一致；同构让两张卡行为一致 |

## 4. 「当前字时值偏差」的算法

### 4.1 为什么不能靠在字附近找发声帧

`wordDeviations` 的注释（`:1524-1527`）已经记过这个坑：**学生连着唱时字间没有静音，在字起点附近找发声帧，找出来的永远是搜索窗的左边缘**，算出来恒 ≈ 0，与学生唱得准不准无关。

而**库里的真实歌词是无缝的**——实测 segment 79 的 28 条逐字数据与 segment 1 的 2 条，`end` 恒等于下一个字的 `start`，零间隙：

```
0.0→0.6, 0.6→1.2, 1.2→1.9, 1.9→2.5, 2.5→3.1, … 16.2→16.8, 16.8→44.7
```

所以"字与字之间有气口"这个前提**不存在**，任何基于发声帧切分的设计（无论切时值还是切起唱）在真实数据上都会退化。

### 4.2 站得住的路子：DTW 映射

页面已经在用的那条路——跑 DTW 对齐，**从映射里读**。对齐按音高轨迹走，学生把一个音拖长，映射会把乐谱上那段压到更长的学生时间里；学生整体晚 0.5s，映射会把每个字对到 +0.5s 的学生时刻。两个量都看得见，且都不受"有没有气口"影响。

**算法**（每 500ms 对已累积的 `studentPoints` 重跑一次）：

1. `tea = thinTeacher(teacherPoints, studentPoints.length, DTW_MAX_CELLS)` —— 与停录后同一套抽稀（`:1671`）。
2. `mapping = dtwAlign(studentPoints, tea, { bandSec: RHYTHM_BAND_SEC })` —— 与停录后同一个对齐函数。
3. 逐字时值偏差：对每个有音高的字 k，取乐谱上离 `ly.start` 与 `ly.start + ly.duration` 最近的样本点下标 `jFrom` / `jTo`（距离超过 `WORD_MATCH_SEC = 0.15s` 就跳过该字，与 `wordDeviations` 同判据），则

   ```
   actual_k = stu[mapping[jTo]].t − stu[mapping[jFrom]].t
   diff_k   = actual_k − ly.duration          ← 卡片主数
   ```

   **不引用下一个字**：本字的乐谱终点由 `start + duration` 直接给出，这对最后一个字同样成立。
4. 卡片取**最近一个已完成字**（`index ≤ widx − 1`）的 `diff_k`。

起唱偏差与它**同源同映射**，一并读出不占主数、只进日志：

```
起唱偏差_k = stu[mapping[jFrom]].t − ly.start
```

### 4.3 可信度门限

`rhythmMetrics` 已经在用 `tempo ∈ [0.5, 2]` 判"这次对齐有没有意义"（`:1679`，学生多半只唱了半段或唱的压根不是这段时会越界）。实时这一路**照搬同一个判据，不新造标准**：跑完对齐取 `tempo`，越界就整轮不出数、不写日志，卡片维持原读数。

### 4.4 四种典型情形

| 学生实际做的 | 时值偏差（卡片主数） | 起唱偏差（日志） | 对不对 |
|---|---|---|---|
| 与乐谱同步唱 | ≈ 0 | ≈ 0 | ✅ |
| 整段晚 0.5s 起唱、内部节奏照旧 | **≈ 0** | **+0.50s** | ✅ 两件事分得开，这正是分开显示的价值 |
| 把某个字拖长 0.4s | **+0.40s** | 该字 ≈ 0，其后各字开始累积正值 | ✅ |
| 抢拍：某个字提前 0.2s 起 | **−0.20s** | −0.20s | ✅ |

### 4.5 取舍理由

- **用 DTW 而不是找发声帧**：见 §4.1，无缝歌词下只有轨迹对齐能定位学生"唱到谱上的哪儿"。
- **复用 `dtwAlign` / `thinTeacher` / `WORD_MATCH_SEC` / `RHYTHM_BAND_SEC` / `DTW_MAX_CELLS`**：让实时与停录后是同一条链路的两次调用，口径不可能漂，且这些常数与函数已被现有 20 条断言覆盖。
- **门限照搬 `[0.5, 2]`**：见 §4.3。
- **本字的终点取自 `start + duration` 而不是下一个字的 `start`**：对末字同样成立，也不引入对相邻字歌词质量的依赖。

## 5. 卡片读数、配色、空态

### 5.1 节奏偏差（`#valRhythm` / `#trendRhythm` / `#cardRhythm`）

| 状态 | 数值 | 趋势文案 | 配色 |
|---|---|---|---|
| 有数 | `+0.38s` / `−0.02s`（带符号、两位小数） | `↗ 时值偏长` / `↘ 时值偏短` / `✓ 时值准确` | `\|Δ\| ≤ DEV_GOOD_SEC` 绿 / `≤ DEV_WARN_SEC` 黄 / 否则红 |
| 本字还在唱 | 保持上一个字的读数 | 不变 | 不变 |
| 一个字都还没结算 | `--` | `等待起唱…` | 灰（沿用现有重置态） |

**日志**：读数变化时写一条，把同源的起唱偏差一并带出——

```
节奏：时值 +0.38s · 起唱 +0.50s
```

两处相对现状的改动：

1. **趋势文案换词**。现在是「↗ 偏慢」（`:1366`），那是**速度**的话术；时值偏差说的是"这个字唱长了还是短了"，两回事。改为「时值偏长／偏短／准确」。
2. **阈值放宽**。现在的 `0.04 / 0.08`（`:1386-1389`）是配那几个假值编出来的，`0.04s` 对一个 0.6s 的字只有 7%，实测会长期显红。改为 `DEV_GOOD_SEC = 0.10` / `DEV_WARN_SEC = 0.25`，约一个十六分音符的容差量级。两个常数只被配色用到，放 `updateMetrics` 上方的显示常量区，等真实素材标定后好调——与 `parse_service` 的 `TOP_DB` 同样的态度。

### 5.2 气息稳定性（`#valBreath` / `#trendBreath` / `#cardBreath`）

| 状态 | 数值 | 趋势文案 | 配色 |
|---|---|---|---|
| 有数 | `85%`（整数） | `✓ 气息稳定` / `⚠ 气息波动` | `≥80` 绿 / `≥70` 黄 / 否则红（沿用现状，不动） |
| 一次长音都没唱完 | `--` | `等待长音…` | 灰 |

**波动系数进日志**：长音结算时写一条，形如

```
气息：稳定度 85% · 能量波动 15% · 长音 3 段
```

段数取 `breathMetrics` 已返回的 `sustainCount`，措辞与停录后那条日志（`:1698`）对齐。只有读数真的变了才更新卡片和写日志——节流每 500ms 重算一次，同一段已完成的长音会被反复结算出同一个值，不去重会把日志刷屏。

### 5.3 稳定度式子去重

稳定度当前写在停录后流程里：`Math.max(0, Math.round((1 - Math.min(1, breath.cv)) * 100))`（`:1693`）。本轮把它提成纯算法段内的 `breathScoreFromCv(cv)`，**实时卡片与停录后维度面板共用同一个函数**，两处的「气息」数字在数学上不可能漂移，并顺带多一个可测的纯函数。

### 5.4 气息口径说明

气息的长音段判定（落点连续 + 音高 ±0.5 半音不动 + 时长 ≥0.4s，见 `breathMetrics`）**完全不读歌词**，所以它出数不要求"唱满一个字"，只要有一串 0.4s 以上的平稳发声就算——这与 PRD 2.10「长音段能量波动系数」的字面一致。也正因为不读歌词，**气息这一路完全不受 §4.1 那个"歌词无缝"问题的影响**，`breathMetrics` 原样复用即可。

## 6. 数据流与分层

```
recordLoop(now)                                          ← :1281-1331
  ├─ 检测落点 → studentPoints.push({t, f0, pitch, rms})  ← 已有，:1305-1314
  ├─ widx 推进 / showCoaching                            ← 已有，:1316-1322
  ├─ updateMetrics(elapsed, seg, widx)                   ← :1324，只留音准那半
  │                                                        （删 :1354-1395 的查表假值段）
  └─ 节流 500ms → updateLiveMetrics()                     ← 新增，一行
                       ├─ tea     = thinTeacher(teacherPoints, stu.length, DTW_MAX_CELLS)
                       ├─ mapping = dtwAlign(stu, tea, {bandSec: RHYTHM_BAND_SEC})
                       ├─ tempo   = rhythmMetrics(stu, tea, mapping).tempo   ← 门限用
                       ├─ wordDurationByMapping(stu, tea, mapping, lyrics)   [纯函数·新增]
                       ├─ wordDeviations(stu, tea, mapping, lyrics)          [纯函数·复用·取起唱]
                       ├─ breathMetrics(stu)                                 [纯函数·复用]
                       └─ breathScoreFromCv(cv)                              [纯函数·新增]
                              ↓
                       写卡片；读数变化时才 addLog
```

**分层**：所有算术在 `BEGIN/END 纯算法` 段内（`:1420-1639`，可被测试脚本原样抽取）；`updateLiveMetrics()` 是段外一层只碰 DOM 的薄壳。节流时间戳、上次读数缓存、日志去重都住在薄壳里，不进算法段。**节流本身属于调度**，故 `LIVE_CALC_INTERVAL_MS` 也放段外，在 `DETECT_INTERVAL_MS`（`:664`）旁边。

**顺带去重**：`wordDeviations`（`:1528-1547`）里那段"找离字起点最近的乐谱点"的内联循环，与新函数要用的是同一段逻辑。提成纯函数 `nearestTeacherIdx(tea, t)`（超出 `WORD_MATCH_SEC` 返回 `-1`）两处共用，`wordDeviations` 改为调用它——它已有的 3 条断言就是这个重构的护栏。

**停录**：`stopAll()` 仍把两张卡重置为 `--`（决策 3），额外清掉节流时间戳与读数缓存，下次录音从头来。重置的位置和写法沿用 `:1833-1842`，不新增函数。

**与停录后面板的关系**：两条链路**共用同一套对齐原语，但读的是映射上不同的量**——实时卡片是「逐字时值偏差（秒）」，停录后维度面板的「节奏」是「整段 DTW 抖动 → logistic（分）」（`:1678-1689`）。单位不同、粒度不同，不冲突；PRD 2.9 只管实时卡片，面板那套本轮不动。

## 7. 新增常数

| 常数 | 值 | 位置 | 理由 |
|---|---|---|---|
| `LIVE_CALC_INTERVAL_MS` | 500 | 段外，`DETECT_INTERVAL_MS`（`:664`）旁 | 节流属于调度、不属于算法；500ms 是 DTW 开销（§11 第 2 条）与读数及时性的折中 |
| `DEV_GOOD_SEC` | 0.10 | 段外，`updateMetrics` 上方的显示常量区 | 时值偏差绿色阈值（秒），只被配色用到 |
| `DEV_WARN_SEC` | 0.25 | 同上 | 时值偏差黄色阈值（秒） |

**不新增算法常数**：`LIVE_ONSET_TOL` 随旧方案一起作废（§4.1 已说明它为什么行不通）。其余一律复用现有常数。

## 8. 容错

每条都能在真实数据里触发（延续 `demo_library.html` 的教训：一个 `null` 上的 `.toFixed()` 会抛 TypeError 打断整张列表的 `map`）。

| 情况 | 触发场景 | 处理 |
|---|---|---|
| `currentLyrics` 为空 | 解析产出的新段落常态 | `updateLiveMetrics` 直接 return，卡片维持 `--`，不报错 |
| `teacherPoints.length < 2` | 歌词全是标点 / 段落 `duration` 为空 | 整轮跳过（`drawTeacherCurve` 已有同样判据，`:954`） |
| `studentPoints.length < 2` | 刚开录、麦克风没授权 | 整轮跳过 |
| 对齐不可信（`tempo` 越界） | 学生只唱了半段 / 唱的不是这段 | 整轮不出数、不写日志，卡片维持原读数；判据与 `:1679` 完全一致 |
| `start` / `duration` 为 `null` | C3 字段可空 | 该字跳过，不给偏差 |
| 标点（`pitch === null`） | 每段都有 | 跳过，与 `wordDeviations` 同规则 |
| 某个字算不出来 | 映射在该字处不单调（`jTo <= jFrom`） | 跳过该字，取更早一个能算的——**不回溯超过 3 个字**，免得卡片停在很陈的读数上 |
| `cv` 为 `null` | 全段没有 ≥0.4s 的平稳音 | 卡片 `--` +「等待长音…」，不写日志 |
| 值为 `null` 却写进 DOM | — | 宁可 `--`，绝不拼出 `"null%"`：`width:null%` 会静默变 0 宽、`textContent = null` 会显示 "null" |

## 9. 测试（`scripts/test_sing_along_algo.js`）

抽取机制**一个字都不用改**——算法段还是 `BEGIN/END` 标记之间的代码，`vm` 里还是只给 `Math`（`:39`）。要改的只有 `ALGO_NAMES`（`:17-20`）加 `wordDurationByMapping`、`breathScoreFromCv`、`nearestTeacherIdx` 三个名字，再补断言。断言由 20 条增至约 32 条。

### 9.1 `wordDurationByMapping`（新增 6 条）

用现有的 `LYRICS` / `teacherFromLyrics` / `singAlong` 合成数据（`:165-169`、`:304-335`），走真实的 `thinTeacher → dtwAlign → wordDurationByMapping` 顺序。

| 断言 | 构造 | 钉住的是什么 |
|---|---|---|
| 准时唱 → 每字偏差 ≈ 0 | `singAlong(LYRICS, 1.0, 0.03, 0.15)` | 基线 |
| **整段晚 0.5s 起唱 → 时值偏差仍 ≈ 0** | 落点时间整体 +0.5 | **口径正确性的核心**：整体偏移不该记进时值 |
| 拖长某字 → 该字偏差明显为正 | 手工构造：某字的音高多保持 0.4s | 时值偏差看得见拖长 |
| 整段慢 10% → 每字偏差 ≈ +0.05s（10% × 0.5） | `singAlong(LYRICS, 1.1, …)` | 慢一成的量化正确性 |
| 标点 / `start` 为 `null` → 不进明细 | `LYRICS.concat([标点])`（`:202-205` 手法） | 脏数据不打断 |
| 空 `lyrics` / 空 `mapping` → 空 `items`，不崩 | `[]` | 空输入安全 |

第 2 条是这套口径的**验收标准**：它把"整体偏移"和"时值"分开，正是 §4.4 表格第二行。

### 9.2 `nearestTeacherIdx`（新增 2 条）

窗内有样本 → 返回最近的那个下标；窗内没有（距离 > `WORD_MATCH_SEC`）→ 返回 `-1`。它是 `wordDeviations` 重构后的依赖，必须有独立断言。

### 9.3 `breathScoreFromCv`（新增 5 条）

`cv = 0 → 100`、`0.15 → 85`、`1 → 0`、`cv > 1` 仍钳在 `0`（不出负数）、`cv = null → null`。

### 9.4 端到端（新增 1 条）

按页面里**真实的调用顺序**串一遍实时链路：推落点 → 节流 → `thinTeacher` + `dtwAlign` + `rhythmMetrics`（取 `tempo` 门限）+ `wordDurationByMapping` + `breathMetrics` + `breathScoreFromCv`，断言"整段拖慢一成之后，时值偏差全部为正、气息稳定度不为 `null`"。现有端到端（`:350-369`）测的是停录后面板的顺序，两者并存。

### 9.5 顺带一致化

现有端到端的 `runPipeline`（`:346`）里手写了一遍稳定度式子，改成调 `algo.breathScoreFromCv`——测试脚本模拟的必须是页面真正走的那个函数，而不是一个复制品。这正是这个脚本存在的意义（见其文件头注释 `:4-6`）。

## 10. 非目标（明确不做）

- **不碰停录后的评分流程**。`simulateAnalysisAfterRecord` 的音准/节奏/气息口径、维度面板、`wordDeviations` 的输出契约，全部维持原样（`wordDeviations` 只做内部去重重构，行为不变）。
- **不碰音准实时卡片**。`updateMetrics` 里音准那半已经是真的，只删它下面那段查表假值。
- **不碰咬字 / 拖腔**。这两项仍是 `score × 随机数` 的模拟（`:1729-1730`），等接后端 B 组（`analyze_service._dimensions`）时一起换真。

## 11. 已知限制

1. **依赖学生音高大致唱对**。DTW 按音高轨迹对齐；音高唱得很偏时对齐本身就不可信，§4.3 的 `tempo ∈ [0.5, 2]` 门限是唯一护栏，越界即整轮不出数。这与停录后维度面板是同一个护栏、同一处风险。
2. **每 500ms 一次 O(n·m) 的 DTW，是本页第一次在录音循环里做这种量级的计算**。真实段落 19.5s 下：学生约 640 点、教师约 975 点、带宽 ±3s 下约 20 万格，`mapping` 的 `Float64Array(n*m)` 约 5MB 临时数组。按 §4 的口径这是为了绕开 §4.1 的退化而必须付的代价。**若实测掉帧**，退路按优先级是：放宽 `LIVE_CALC_INTERVAL_MS` → 对 `studentPoints` 也做抽稀。
3. **两张卡与停录后面板口径不同**（时值秒 vs DTW 抖动分）。这是有意的，见 §6；不要试图把两个数统一起来。
4. **阈值未用真实素材标定**。`DEV_GOOD_SEC` / `DEV_WARN_SEC` 是按"一个十六分音符的容差量级"估的，与 `TOP_DB` 一样属于待标定常数。
5. **每个字的读数最多滞后一个字**（决策 1）。这是拿读数稳定性换来的，不是缺陷。
