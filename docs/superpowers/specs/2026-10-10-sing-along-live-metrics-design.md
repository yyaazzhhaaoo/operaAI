# 实时跟唱页（`sing_along.html`）实时节奏偏差与气息稳定性 实现设计

日期：2026-10-10 ｜ 状态：已评审待实现 ｜ 关联：《1-PRD-V1.0》2.9 / 2.10；`scripts/test_sing_along_algo.js`；`2026-10-09-sing-along-list-and-demo-playback-design.md`

## 1. 背景与目标

`sing_along.html` 的录音区有四张实时指标卡。其中**音准**已经是真的（`updateMetrics` 取离当前时刻 0.1s 内最近的学生落点，与教师该字的 `pitch` 求音分差，`:1333-1352`），另外两张——

- **节奏偏差 (秒)**（`#valRhythm`，`:595-599`）
- **气息稳定性**（`#valBreath`，`:601-605`）

—— 是**按当前唱到第几个字 `widx` 查表的硬编码值**（`:1354-1395`）：`widx===2` 就显示 `+0.08s / 72%`，`widx∈{0,1}` 显示 `+0.02s / 88%`，其余 `+0.03s / 82%`。与音频、与学生实际唱成什么样**毫无关系**。

**目标**：把这两张卡改成用真实录音数据计算，并让新写的算法**纳入 `scripts/test_sing_along_algo.js` 的覆盖范围**——这是本轮做这件事的起因：该脚本是页面「纯算法」段的唯一测试手段，而这两张卡之所以一直是假的，部分原因就是它们原先长在碰 DOM 的 `updateMetrics` 里，抽不进那个脚本。

**不做**：后端一行不动，不新增接口，不动停录后的评分流程。

## 2. 需求原文：PRD 2.9 / 2.10

《1-PRD-V1.0》对这两项有明确定义，且与页面现状**不是一回事**：

| 编号 | PRD 原文（段落摘自 `word/document.xml`） | 页面现状 |
|---|---|---|
| 2.8 实时音准偏差显示 | 当前字与老师音高差（音分）实时显示 | ✅ 已真实实现 |
| 2.9 **实时节奏偏差显示** | **当前字时值与标准值偏差（秒）显示** | ❌ 硬编码 |
| 2.10 **实时气息稳定性显示** | **长音段能量波动系数（%）显示** | ❌ 硬编码 |

两条原文决定了本轮的口径：2.9 要的是**时值**（一个字的持续时间），不是速度、也不是整段偏移；2.10 要的是**长音段**上的能量统计，不是整段的。

## 3. 已确认的四个口径决策

以下四条在评审中逐条确认，是本设计其余部分的约束：

| # | 议题 | 决策 | 理由 |
|---|---|---|---|
| 1 | 字还没唱完时卡片显示什么 | **字结束时才定格**，进行中保持上一个字的最终读数 | 一个字的时值本来就是事后量；"进行中显示已唱−标准"会在每个字开头甩出一个大负数，让人误以为一直抢拍 |
| 2 | 气息显示稳定度还是波动系数 | **主数显示稳定度 `(1−CV)×100%`，波动系数写进日志** | PRD 2.10 的字面是波动系数，但卡片名叫「气息稳定性」，且停录后维度面板用的是稳定度；两者方向相反，同一页并存会让人以为哪个算错了 |
| 3 | 停录后卡片怎么办 | **重置为 `--`** | 卡片定位是「录音中的实时指示」，录音结束后的权威结论由维度面板承担，各司其职 |
| 4 | 长音还在唱时要不要实时刷 | **长音段结束才定格**，与决策 1 同构 | 半截数据的 CV 抖动大、且与停录后口径不一致；同构让两张卡行为一致 |

## 4. 「一个字实际唱了多久」的算法

PRD 只给了一句「当前字时值与标准值偏差（秒）」，具体量法由本设计定义。

**输入**：`studentPoints`（`{t, f0, pitch, rms}`，只在有有效基频的帧落点，约 33 帧/秒）、`currentLyrics`（C3 给的逐字歌词，字段 `char / pitch / start / duration / tip`）、当前 `widx`。

**步骤**（对字 k）：

1. **找起唱**：`onset_k` = 落在 `[ly.start − LIVE_ONSET_TOL, ly.start + ly.duration]` 窗内的**第一个尚未被认领的**落点。窗左放宽 `LIVE_ONSET_TOL = 0.3s` 是为了容忍抢拍。
2. **取发声段**：从 `onset_k` 向右走，相邻落点间隔 > `BREATH_FRAME_GAP_SEC`（0.1s）即断开——这一段就是"这个字唱出去的声音"。
3. **认领**：字 k 认领**整条发声段**（不只是 `onset` 那一个点），按字序依次进行，已被认领的落点不再给后面的字。
4. **截断**：段的右端截到 `onset_{k+1}`（下一个字的起唱），末字截到录音中最后一个落点，免得把下一个字的声音算进来。
5. **实际时值** `= 截断后这段的时长`；**偏差** `= 实际时值 − ly.duration`。

第 3 步的"认领整条段"是第 4 步成立的前提：学生连唱不换气时整串落点连成一段，字 k 认走它之后，字 k+1 在自己窗内找不到未认领的落点，于是**认不到 `onset`、给不出偏差**——这正是 §11 第 1 条限制的来源。

**四种典型情况**：

| 学生实际做的 | 量出的时值 | 偏差 | 是否符合直觉 |
|---|---|---|---|
| 准时唱一个 0.6s 的字 | 0.58s | `−0.02s` | ✅ |
| 把这个字拖到 1.0s，下一个字顺势延后 | 0.98s | `+0.38s` | ✅ 正是 2.9 要测的 |
| 字间换一口气再唱下一个字 | 0.58s（气口被 0.1s 断点切掉） | `−0.02s` | ✅ 气口不算进时值 |
| 下一个字抢拍提前起唱 | 0.48s | `−0.12s` | ✅ 本字确实被截短了 |

**三处取舍的理由**：

- **锚 `onset` 而不是锚字的乐谱区间**：若按 `[ly.start, ly.start+duration)` 截取，"拖长音"超出区间的部分会被丢弃，报成"偏短"，方向正好反了。
- **用 0.1s 断点剔除气口**：戏曲字间换气很常见，不剔除会让每个字的时值都系统性偏长。
- **复用 `BREATH_FRAME_GAP_SEC`**：让"什么算一次连续发声"在页面上只有一个定义，不新造常数。

## 5. 卡片读数、配色、空态

### 5.1 节奏偏差（`#valRhythm` / `#trendRhythm` / `#cardRhythm`）

| 状态 | 数值 | 趋势文案 | 配色 |
|---|---|---|---|
| 有数 | `+0.38s` / `−0.02s`（带符号、两位小数） | `↗ 时值偏长` / `↘ 时值偏短` / `✓ 时值准确` | `\|Δ\| ≤ DEV_GOOD_SEC` 绿 / `≤ DEV_WARN_SEC` 黄 / 否则红 |
| 本字还在唱 | 保持上一个字的读数 | 不变 | 不变 |
| 一个字都还没结算 | `--` | `等待起唱…` | 灰（沿用现有重置态） |

两处相对现状的改动：

1. **趋势文案换词**。现在是「↗ 偏慢」（`:1366`），那是**速度**的话术；时值偏差说的是"这个字唱长了还是短了"，两回事。改为「时值偏长／偏短／准确」。
2. **阈值放宽**。现在的 `0.04 / 0.08`（`:1386-1389`）是配那几个假值编出来的，`0.04s` 对一个 0.6s 的字只有 7%，实测会长期显红。改为 `DEV_GOOD_SEC = 0.10` / `DEV_WARN_SEC = 0.25`，约一个十六分音符的容差量级。两个常数放纯算法段顶部，等真实素材标定后好调——与 `parse_service` 的 `TOP_DB` 同样的态度。

### 5.2 气息稳定性（`#valBreath` / `#trendBreath` / `#cardBreath`）

| 状态 | 数值 | 趋势文案 | 配色 |
|---|---|---|---|
| 有数 | `85%`（整数） | `✓ 气息稳定` / `⚠ 气息波动` | `≥80` 绿 / `≥70` 黄 / 否则红（沿用现状，不动） |
| 一次长音都没唱完 | `--` | `等待长音…` | 灰 |

**波动系数进日志**：长音结算时写一条，形如

```
气息：稳定度 85% · 能量波动 15% · 长音 3 段
```

段数取 `breathMetrics` 已返回的 `sustainCount`，措辞与停录后那条日志（`:1698`）对齐。不写"最近一段长音多长"——`breathMetrics` 不返回单段时长，为一行日志加一个返回字段不划算。

**只有读数真的变了才更新卡片和写日志**。节流每 250ms 重算一次，同一段已完成的长音会被反复结算出同一个值；不做去重会把日志刷屏。

### 5.3 稳定度式子去重

稳定度当前写在停录后流程里：`Math.max(0, Math.round((1 - Math.min(1, breath.cv)) * 100))`（`:1693`）。本轮把它提成纯算法段内的 `breathScoreFromCv(cv)`，**实时卡片与停录后维度面板共用同一个函数**，两处的「气息」数字在数学上不可能漂移，并顺带多一个可测的纯函数。

### 5.4 口径说明

气息的长音段判定（落点连续 + 音高 ±0.5 半音不动 + 时长 ≥0.4s，见 `breathMetrics`）**完全不读歌词**，所以它出数不要求"唱满一个字"，只要有一串 0.4s 以上的平稳发声就算——这与 PRD 2.10「长音段能量波动系数」的字面一致。

## 6. 数据流与分层

```
recordLoop(now)                                          ← :1281-1331
  ├─ 检测落点 → studentPoints.push({t, f0, pitch, rms})  ← 已有，:1305-1314
  ├─ widx 推进 / showCoaching                            ← 已有，:1316-1322
  ├─ updateMetrics(elapsed, seg, widx)                   ← :1324，只留音准那半
  │                                                        （删 :1354-1395 的查表假值段）
  └─ 节流 250ms → updateLiveMetrics()                     ← 新增，一行
                       ├─ wordDurationDeviation(stu, lyrics, widx - 1)  [纯函数·新增]
                       ├─ breathMetrics(stu)                            [纯函数·复用]
                       └─ breathScoreFromCv(cv)                         [纯函数·新增]
                              ↓
                       写卡片；读数变化时才 addLog
```

**分层**：所有算术在 `BEGIN/END 纯算法` 段内（`:1420-1639`，可被测试脚本原样抽取）；`updateLiveMetrics()` 是段外一层只碰 DOM 的薄壳。节流时间戳、上次读数缓存、日志去重都住在薄壳里，不进算法段。

**`wordDurationDeviation` 的入参**是 `widx − 1`——当前字还在唱，能结算的只有它前面那个。算得出就返回该字的偏差，**算不出就返回 `null`，函数不回溯到更早的字**：回溯找到的只会是更陈的读数，而薄壳在收到 `null` 时保持卡片原样不动，效果与"保持上一个字的读数"（决策 1）完全一致，且不需要多一层逻辑。

**停录**：`stopAll()` 仍把两张卡重置为 `--`（决策 3），额外清掉节流时间戳与读数缓存，下次录音从头来。重置的位置和写法沿用 `:1833-1842`，不新增函数。

**与停录后面板的关系**：两条链路**口径不同、有意为之**——实时卡片是「字时值偏差（秒）」，停录后维度面板的「节奏」是「DTW 抖动 → logistic（分）」（`:1678-1689`）。单位不同不冲突，但正因如此**不要**试图把两个数统一起来；PRD 2.9 只管实时卡片，面板那套本轮不动。

## 7. 新增常数

| 常数 | 值 | 位置 | 理由 |
|---|---|---|---|
| `LIVE_ONSET_TOL` | 0.3 | 纯算法段内 | 起唱搜索窗左侧放宽量（容忍抢拍）；测试要抽到，故必须段内 |
| `DEV_GOOD_SEC` | 0.10 | 纯算法段内 | 时值偏差绿色阈值（秒） |
| `DEV_WARN_SEC` | 0.25 | 纯算法段内 | 时值偏差黄色阈值（秒） |
| `LIVE_CALC_INTERVAL_MS` | 250 | 段外，`DETECT_INTERVAL_MS`（`:664`）旁 | **节流属于调度、不属于算法**，不进算法段 |

## 8. 容错

每条都能在真实数据里触发（延续 `demo_library.html` 的教训：一个 `null` 上的 `.toFixed()` 会抛 TypeError 打断整张列表的 `map`）。

| 情况 | 触发场景 | 处理 |
|---|---|---|
| `currentLyrics` 为空 | 解析产出的新段落常态 | `updateLiveMetrics` 直接 return，卡片维持 `--`，不报错 |
| `start` / `duration` 为 `null` | C3 字段可空 | 该字跳过，不给偏差 |
| 标点（`pitch === null`） | 每段都有 | 跳过，与 `wordDeviations`（`:1528-1547`）同规则 |
| 一个字都没结算出来 | 学生没出声 / 麦克风没授权 | 卡片维持 `--`，**不写日志**——不能把"没测出来"记成一条读数 |
| `cv` 为 `null` | 全段没有 ≥0.4s 的平稳音 | 卡片 `--` +「等待长音…」，不写日志 |
| 值为 `null` 却写进 DOM | — | 宁可 `--`，绝不拼出 `"null%"`：`width:null%` 会静默变 0 宽、`textContent = null` 会显示 "null" |

**性能**：`breathMetrics` 含一次排序，O(N log N)，N ≈ 33 × 段落时长（真实段落 11.2 / 19.5s → 约 370 / 640 个点），250ms 一次可忽略，不需额外优化。

## 9. 测试（`scripts/test_sing_along_algo.js`）

抽取机制**一个字都不用改**——算法段还是 `BEGIN/END` 标记之间的代码，`vm` 里还是只给 `Math`（`:39`）。要改的只有 `ALGO_NAMES`（`:17-20`）加 `wordDurationDeviation`、`breathScoreFromCv` 两个名字，再补断言。断言由 20 条增至约 32 条。

### 9.1 `wordDurationDeviation`（新增 6 条）

| 断言 | 构造 |
|---|---|
| 准时唱 → 每字偏差 ≈ 0 | 现有 `singAlong(lyrics, 1.0, …)` 手法 |
| 拖长某字 → 该字偏差明显为正 | 手工造一段拖长的落点 |
| 字间换气 → 气口不计入时值，偏差仍 ≈ 0 | 两个字之间挖一个 > 0.1s 的洞 |
| 下一个字抢拍 → 前一字报偏短 | 后续落点整体前移 |
| 标点 / `start: null` 不进明细 | 复用现有 `LYRICS.concat([标点])` 手法（`:202-205`） |
| 整串连唱不断 / 落点为空 → 返回 `null`，不崩 | 落点间距全部 < 0.1s；以及空数组 |

最后一条是这套设计的**安全底线**：算不出来就返回 `null`，绝不吐一个数。测试要把它钉死。

### 9.2 `breathScoreFromCv`（新增 5 条）

`cv = 0 → 100`、`0.15 → 85`、`1 → 0`、`cv > 1` 仍钳在 `0`（不出负数）、`cv = null → null`。

### 9.3 端到端（新增 1 条）

按页面里**真实的调用顺序**串一遍实时链路：推落点 → 节流 → `wordDurationDeviation` + `breathMetrics` + `breathScoreFromCv`，断言"整段拖慢一成之后卡片读数确实变正"。现有端到端（`:350-369`）测的是停录后面板的顺序，两者并存。

### 9.4 顺带一致化

现有端到端的 `runPipeline`（`:346`）里手写了一遍稳定度式子，改成调 `algo.breathScoreFromCv`——测试脚本模拟的必须是页面真正走的那个函数，而不是一个复制品。这正是这个脚本存在的意义（见其文件头注释 `:4-6`）。

## 10. 非目标（明确不做）

- **不碰停录后的评分流程**。`simulateAnalysisAfterRecord` 的音准/节奏/气息口径、维度面板、`wordDeviations` 的逐字起唱偏差，全部维持原样。
- **不碰音准实时卡片**。`updateMetrics` 里音准那半已经是真的，只删它下面那段查表假值。
- **不碰咬字 / 拖腔**。这两项仍是 `score × 随机数` 的模拟（`:1729-1730`），等接后端 B 组（`analyze_service._dimensions`）时一起换真。
- **不接 D1/D2/D3、不接 CI**。本目录没有 CI 配置，脚本继续手动 `node scripts/test_sing_along_algo.js` 跑。
- **不新增依赖**。

## 11. 已知限制

1. **学生连唱不换气时，一个字可能算不出时值**。整串落点连成一段、中间没有 > 0.1s 的断点，那么只有第一个字能认到 `onset`，其后几个字返回 `null`，卡片维持上一个读数（一个字都没结算过则维持 `--`）。这是"宁可不出数也不出假数"的取舍，与停录后 `breathMetrics` 对空长音段的处理一致；抢拍/拖拍的整体趋势由停录后的维度面板兜底。
2. **两张卡与停录后面板的口径不同**（秒 vs 分，字时值 vs DTW 抖动）。这是有意的，见 §6。
3. **阈值未用真实素材标定**。`DEV_GOOD_SEC` / `DEV_WARN_SEC` 是按"一个十六分音符的容差量级"估的，与 `TOP_DB` 一样属于待标定常数。
